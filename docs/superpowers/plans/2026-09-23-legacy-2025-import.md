# Histórico 2025 — Legacy ERP Data Import Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One-time import of January 2025–February 2026 sales/returns data from the pre-migration Profit Plus server into brand-new `_Legacy` dimension/fact tables, plus a new, fully isolated "Histórico 2025" Analítica tab — with zero blending into current-era data or queries.

**Architecture:** A new migration creates `Dim_Customer_Legacy`/`Dim_Product_Legacy`/`Dim_SalesRep_Legacy`/`Fact_Sales_Legacy`/`Fact_Returns_Legacy`, all FK'd only to each other (plus the shared `dim.Dim_Date`) — never to the current-era `Dim_Customer`/`Dim_Product`/`Dim_SalesRep`/`Fact_Sales`/`Fact_Returns`. A new standalone script (`scripts/dwh-legacy-2025-import.ts`, outside the tracked `migrations/` system) opens two separate `mssql` connections — one to the DWH, one to the legacy server via new `LEGACY_DB_*` env vars — and does a single guarded load, never repeated. A new `app/api/dwh/historico/route.ts` mirrors `ventas/route.ts`'s `section`/`groupBy` dispatch shape against the legacy tables, minus date-range picking, prev-period comparison, and the entidad/tienda toggle (none of which apply to this fixed, flat dataset). A new `tab-historico.tsx` mirrors `tab-ventas.tsx`'s UX plus a permanent disclaimer banner.

**Tech Stack:** Next.js 16 App Router, `mssql`, Bun test runner, TypeScript, React, Recharts.

**Spec:** `docs/superpowers/specs/2026-09-23-legacy-2025-import-design.md`

**Sequence:** 4th of 4 planned changes from this brainstorming session. (1) `2026-09-23-historical-usd-conversion.md` — plan written, NOT yet executed; this plan has a **soft** dependency on it (see Global Constraints). (2) `2026-09-23-seller-product-store-matrix.md` — plan written, NOT yet executed; no relationship to this plan. (3) The `migrations/` directory reorg — **already executed and committed** (`dwh-migrations/` → `migrations/dwh/`, etc.) — this plan uses the current real path `migrations/dwh/` throughout, not the spec document's now-stale `dwh-migrations/` wording. (4) **this plan.**

## Global Constraints

- **Soft dependency, not a blocker:** `app/api/dwh/lib/query-builder.ts` today exports `getUsdRate(): Promise<number | null>` (single current-rate lookup) — the historical-usd-conversion plan's Task 1 will eventually replace/augment this with `usdConversionJoin(factAlias, dateColumn?)` / `dualAmountExpr(factAlias, column, bsAlias, usdAlias)` and a shared `DualAmount { bs: number; usd: number | null }` type, but **that plan has not been executed yet** — confirmed live: `query-builder.ts` still only has `getUsdRate()`, and `tab-ventas.tsx` still calls the old `moneyLabel(value, currency, rate)`/`money(v, currency, rate)` signature with a bare `usdRate: number | null` response field. This plan's route/types/tab therefore use the **current, real, pre-fix shape** (`usdRate: number | null` sibling field + bare `number` money fields + `getUsdRate()`), exactly matching every other route in the codebase today. **Do not invent `DualAmount`/`usdConversionJoin` calls that don't exist yet.** If the historical-usd-conversion plan executes BEFORE this one, whoever picks this plan up should migrate Task 4's route to the new shared helpers as a small follow-up — not a reason to block this plan.
- Scope: sellers, products, customers, invoices (sales + returns) only. No collections/AR/purchases/expenses/cash-movement legacy tables — this plan never touches `Fact_Collections`, `Fact_AR_Snapshot`, `Fact_Purchases`, `Fact_Expenses`, or `Fact_CashMovements`.
- No blending: every new table is `_Legacy`-suffixed and FK'd only to other `_Legacy` tables (plus the shared `dim.Dim_Date`). No existing route, type, or component is modified by this plan except `analitica-client.tsx`'s `TABS` array (Task 6, additive only).
- No cross-referencing of old codes against current dimensions anywhere — `Dim_Customer_Legacy`/`Dim_Product_Legacy`/`Dim_SalesRep_Legacy` are loaded straight from the legacy server with no lookup against `Dim_Customer`/`Dim_Product`/`Dim_SalesRep`.
- Fixed date window: `2025-01-01` through `2026-02-28` inclusive (2026 is not a leap year). This exact boundary is used everywhere a date filter appears in this plan — never hardcode `02-29`.
- Migration numbering: current highest file in `migrations/dwh/` is `0032_backfill_legalentitykey_noncurrent.sql` (confirmed via `ls migrations/dwh/*.sql`) — the seller-product-store-matrix plan (executes before this one, per Sequence above) claims `0033_dim_date_add_week.sql`, so this plan's new migration is numbered `migrations/dwh/0034_legacy_2025_schema.sql` to avoid a collision. If plans end up executing out of the stated order, whoever runs second must re-check `ls migrations/dwh/*.sql` and renumber this migration to the next real available number rather than assuming `0034` is still free.
- The one-time import script (`scripts/dwh-legacy-2025-import.ts`) is NOT part of the tracked `migrations/` system — it is a standalone operational script, following the exact structural precedent of `scripts/dwh-backfill.ts` (plain `main()` function, `import.meta.main` guard, no watermark tracking, no `dwh.__dwh_migrations` entry).
- `LEGACY_DB_*` env vars are read only by the new script — never by `getDwhPool()`, `getPool()`, or any other running-app code path.
- Route test convention (confirmed live against `app/api/dwh/ventas/__tests__/route.test.ts`): auth-smoke-tests only — assert 401 for an unauthenticated `GET`, no live-DB integration test at the route level. Use `bun test <path>` (no `--env-file`/`--timeout`/DB needed).
- `migrations/dwh/README.md`'s convention: `IF NOT EXISTS`/`CREATE OR ALTER` for re-runnable safety, multi-batch DDL separated by a line containing only `GO`.
- Every commit ends with `Co-Authored-By: Claude Sonnet 5 <noreply@anthropic.com>`.

import { getDwhPool } from '@/lib/db/dwh-mssql';

// One-time historical backfill, NOT part of the tracked migrations/
// system (unlike migrations/dwh/*.sql, this never re-runs and has no
// dwh.__dwh_migrations entry) — same "standalone operational script"
// framing as scripts/dwh-backfill.ts. Loads Jan 2025-Feb 2026 sales/
// returns data from the pre-March-2026-cutover Profit Plus server into
// the _Legacy dimension/fact tables created by
// migrations/dwh/0034_legacy_2025_schema.sql. See
// docs/superpowers/specs/2026-09-23-legacy-2025-import-design.md for
// why this can't reuse the existing Load_Dim_*/Load_Fact_* machinery
// (different server, one-time load, unmapped customer/product/rep
// identities across the cutover).
//
// The legacy server is expected to be decommissioned after this script
// runs successfully — LEGACY_DB_* env vars are read ONLY here, never by
// the running app.

export const IMPORT_START_DATE = '2025-01-01';
// 2026 is not a leap year (not divisible by 4) — the actual end boundary
// is Feb 28, not Feb 29. Do not "fix" this to 02-29 without re-checking
// the year.
export const IMPORT_END_DATE = '2026-02-28';

function legacyEnv(name: string): string {
  const value = process.env[`LEGACY_DB_${name}`];
  if (value === undefined) {
    throw new Error(`LEGACY_DB_${name} is not set — required to run the Histórico 2025 import`);
  }
  return value;
}

export function buildLegacyConfig(): sql.config {
  return {
    server: legacyEnv('SERVER'),
    port: parseInt(process.env.LEGACY_DB_PORT ?? '1433'),
    database: legacyEnv('NAME'),
    user: legacyEnv('USER'),
    password: legacyEnv('PASSWORD'),
    options: {
      encrypt: (process.env.LEGACY_DB_ENCRYPT ?? 'false') === 'true',
      trustServerCertificate: (process.env.LEGACY_DB_TRUST_SERVER_CERT ?? 'true') !== 'false',
    },
  };
}

export async function getLegacyPool(): Promise<sql.ConnectionPool> {
  return new sql.ConnectionPool(buildLegacyConfig()).connect();

// server — never fact.Fact_Sales/fact.Fact_Returns. No dateRange param:
// the window is fixed and never grows. No entidad/tienda toggle: legacy
// customers have no Dim_LegalEntity rollup (see the schema migration's
// comments for why). No prev-period comparison: there is no meaningful
// "before" this dataset's own start.
const DATE_WINDOW = 'AND fsl.DateKey BETWEEN 20250101 AND 20260228';
const RETURNS_DATE_WINDOW = 'AND frl.DateKey BETWEEN 20250101 AND 20260228';

function monthlyQuery(): string {
  return `
    SELECT
      d.YearMonth AS GroupValue,
      d.YearMonth AS GroupLabel,
      SUM(fsl.NetAmount) AS SalesNet,
      (SELECT ISNULL(SUM(frl.NetAmount), 0)
         FROM fact.Fact_Returns_Legacy frl
         JOIN dim.Dim_Date dr ON dr.DateKey = frl.DateKey
         WHERE dr.YearMonth = d.YearMonth ${RETURNS_DATE_WINDOW}) AS ReturnsNet
    FROM fact.Fact_Sales_Legacy fsl
    JOIN dim.Dim_Date d ON d.DateKey = fsl.DateKey
    WHERE 1 = 1 ${DATE_WINDOW}
    GROUP BY d.YearMonth
    ORDER BY d.YearMonth
  `;
}

function clienteQuery(monthFilter: string, salesRepFilter: string): string {
  return `
    SELECT TOP 15
      CAST(c.CustomerLegacyKey AS varchar(20)) AS GroupValue,
      ISNULL(c.CustomerName, c.CustomerCode) AS GroupLabel,
      SUM(fsl.NetAmount) AS SalesNet,
      (SELECT ISNULL(SUM(frl.NetAmount), 0)
         FROM fact.Fact_Returns_Legacy frl
         WHERE frl.CustomerLegacyKey = c.CustomerLegacyKey ${RETURNS_DATE_WINDOW}
      ) AS ReturnsNet
    FROM fact.Fact_Sales_Legacy fsl
    JOIN dim.Dim_Customer_Legacy c ON c.CustomerLegacyKey = fsl.CustomerLegacyKey
    JOIN dim.Dim_Date d ON d.DateKey = fsl.DateKey
    WHERE 1 = 1 ${DATE_WINDOW} ${monthFilter} ${salesRepFilter}
    GROUP BY c.CustomerLegacyKey, ISNULL(c.CustomerName, c.CustomerCode)
    ORDER BY SalesNet DESC
  `;
}

function lineaQuery(): string {
  return `
    SELECT TOP 15
      ISNULL(p.LineCode, 'SIN_LINEA') AS GroupValue,
      ISNULL(p.LineName, 'Sin línea') AS GroupLabel,
      SUM(fsl.NetAmount) AS SalesNet,
      (SELECT ISNULL(SUM(frl.NetAmount), 0)
         FROM fact.Fact_Returns_Legacy frl
         JOIN dim.Dim_Product_Legacy pr ON pr.ProductLegacyKey = frl.ProductLegacyKey
         WHERE ISNULL(pr.LineCode, 'SIN_LINEA') = ISNULL(p.LineCode, 'SIN_LINEA') ${RETURNS_DATE_WINDOW}) AS ReturnsNet
    FROM fact.Fact_Sales_Legacy fsl
    JOIN dim.Dim_Product_Legacy p ON p.ProductLegacyKey = fsl.ProductLegacyKey
    WHERE 1 = 1 ${DATE_WINDOW}
    GROUP BY ISNULL(p.LineCode, 'SIN_LINEA'), ISNULL(p.LineName, 'Sin línea')
    ORDER BY SalesNet DESC
  `;
}

function lineaProductBreakdownQuery(): string {
  return `
    SELECT TOP 15
      CAST(p.ProductLegacyKey AS varchar(20)) AS GroupValue,
      ISNULL(p.ProductName, p.ProductCode) AS GroupLabel,
      SUM(fsl.NetAmount) AS SalesNet
    FROM fact.Fact_Sales_Legacy fsl
    JOIN dim.Dim_Product_Legacy p ON p.ProductLegacyKey = fsl.ProductLegacyKey
    WHERE ISNULL(p.LineCode, 'SIN_LINEA') = @parentValue ${DATE_WINDOW}
    GROUP BY p.ProductLegacyKey, ISNULL(p.ProductName, p.ProductCode)
    ORDER BY SalesNet DESC
  `;
}

const KPIS_QUERY = `
  SELECT
    SUM(fsl.NetAmount) AS SalesNet,
    SUM(fsl.QuantitySold) AS UnitsSold,
    COUNT(DISTINCT fsl.CustomerLegacyKey) AS ActiveClients,
    COUNT(DISTINCT fsl.InvoiceNumber) AS InvoiceCount
  FROM fact.Fact_Sales_Legacy fsl
  WHERE 1 = 1 ${DATE_WINDOW}
`;

function formatYearMonth(ym: string): string {
  const [y, m] = ym.split('-');
  const names = ['Ene', 'Feb', 'Mar', 'Abr', 'May', 'Jun', 'Jul', 'Ago', 'Sep', 'Oct', 'Nov', 'Dic'];
  const idx = parseInt(m, 10) - 1;
  return names[idx] ? `${names[idx]} ${y.slice(2)}` : ym;
}

async function handleKpis(currency: string) {
  const pool = await getDwhPool();
  const [kpiResult, usdRate] = await Promise.all([
    pool.request().query(KPIS_QUERY),
    currency === 'usd' ? getUsdRate() : Promise.resolve(null),
  ]);

  const row = kpiResult.recordset[0] as { SalesNet: number | null; UnitsSold: number | null; ActiveClients: number; InvoiceCount: number };
  const salesNet = Number(row.SalesNet ?? 0);
  const invoiceCount = Number(row.InvoiceCount ?? 0);

  const kpis: HistoricoKpis = {
    salesNet,
    activeClients: Number(row.ActiveClients ?? 0),
    avgTicket: invoiceCount > 0 ? salesNet / invoiceCount : null,
    unitsSold: Number(row.UnitsSold ?? 0),
  };

  const response: HistoricoKpisResponse = { kpis, usdRate };
  return jsonWithCache(response);
}

export async function GET(request: NextRequest) {
  const auth = await requireDwhAccess(request);
  if (!auth.ok) return auth.response;

  const { searchParams } = new URL(request.url);
  const currency = searchParams.get('currency') ?? 'bs';
  const groupByParam = searchParams.get('groupBy') ?? 'mes';
  const groupBy: GroupBy = groupByParam === 'cliente' || groupByParam === 'linea' ? groupByParam : 'mes';
  const breakdownByParam = searchParams.get('breakdownBy');
  const parentValue = searchParams.get('parentValue');
  const month = searchParams.get('month');
  const salesRepKeyParam = searchParams.get('salesRepKey');
  const salesRepKey = salesRepKeyParam && /^\d+$/.test(salesRepKeyParam) ? Number(salesRepKeyParam) : null;

  const section = searchParams.get('section');
  if (section === 'kpis') {
    try {
      return await handleKpis(currency);
    } catch {
      return NextResponse.json({ error: 'Error al consultar el Data Warehouse' }, { status: 500 });
    }
  }

  try {
    const pool = await getDwhPool();

    if (breakdownByParam === 'producto' && parentValue && groupByParam === 'linea') {
      const req = pool.request();
      req.input('parentValue', parentValue);
      const result = await req.query(lineaProductBreakdownQuery());
      return jsonWithCache({ breakdown: result.recordset.map(r => ({ label: r.GroupLabel, value: String(r.GroupValue), salesNet: Number(r.SalesNet) })) });
    }

    let recordset: Record<string, unknown>[];
    const breadcrumb: HistoricoResponse['breadcrumb'] = [{ label: 'Histórico 2025', groupBy: 'mes' }];

    if (groupBy === 'cliente') {
      const req = pool.request();
      let monthFilter = '';
      if (month) {
        req.input('month', month);
        monthFilter = 'AND d.YearMonth = @month';
      }
      let salesRepFilter = '';
      if (salesRepKey !== null) {
        req.input('salesRepKey', salesRepKey);
        salesRepFilter = 'AND fsl.SalesRepLegacyKey = @salesRepKey';
      }
      const result = await req.query(clienteQuery(monthFilter, salesRepFilter));
      recordset = result.recordset;
      breadcrumb.push({ label: month ? formatYearMonth(month) : 'Clientes', groupBy: 'cliente' });
    } else if (groupBy === 'linea') {
      const result = await pool.request().query(lineaQuery());
      recordset = result.recordset;
      breadcrumb.push({ label: 'Líneas', groupBy: 'linea' });
    } else {
      const result = await pool.request().query(monthlyQuery());
      recordset = result.recordset;
    }

    const usdRate = currency === 'usd' ? await getUsdRate() : null;

    const rows: HistoricoRow[] = recordset.map(r => {
      const salesNet = Number(r.SalesNet);
      const returnsNet = Number(r.ReturnsNet ?? 0);
      const label = groupBy === 'mes' ? formatYearMonth(String(r.GroupLabel)) : String(r.GroupLabel);
      return {
        label,
        value: r.GroupValue as string,
        salesNet,
        returnRate: salesNet > 0 ? returnsNet / salesNet : null,
      };
    });

    const response: HistoricoResponse = { rows, groupBy, breadcrumb, usdRate };
    return jsonWithCache(response);
  } catch {
    return NextResponse.json({ error: 'Error al consultar el Data Warehouse' }, { status: 500 });
  }
}
